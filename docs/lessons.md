# 工程陷阱记录

> 这份文档收集开发过程中**真实踩到并已修复**的陷阱,每条都对应一个回归用例。README 只保留结论,细节在这里。

## 隐私与可见性

| 陷阱 | 症状 | 修法 / 用例 |
| --- | --- | --- |
| **日志泄露暗牌** | 引擎事件 `KICKED` 携带补入的暗牌 id,而日志由 `s.events.map(describeEvent)` 原样下发 —— UI 上牌背朝下,日志里却写着牌面。对 LLM 选手等于免费作弊通道 | `describeEvent(e, { hideCardIds })` 支持脱敏;`view.ts` 按"该查看者看不到的牌"过滤;CLI 与会话工具同步。用例 `WEB-12` |
| **用 `actor` 代替 `viewer` 判断可见性** | 视图里 3 处(池子暗牌 / 封锁列表 / 待截胡窗口)用"当前行动者"判断"该玩家能否看到这张暗牌"。结果:只要踢牌的 AI 正在行动,任何人打开页面都能看到那张暗牌(端到端实测:400 步内 395 次泄露) | 统一改用 `viewerSeat`。用例 `WEB-13`/`WEB-14`;端到端探针复验 0 泄露 |
| **视角跟随了 AI** | 热座(≥2 人类)时"跟随当前行动者",轮到 AI 就把该 AI 的视角给了玩家(手牌 + 它踢出的暗牌) | `viewerSeatFor`:**视角只能落在人类座位**;轮到 AI 时 viewer = null(旁观)。用例 `WEB-13` |

> 通用判据:**凡是把隐藏信息渲染成文本或下发给客户端的地方,都要按"查看者"过滤一遍**,而不是按"行动者"。

## 前端

| 陷阱 | 症状 | 修法 / 用例 |
| --- | --- | --- |
| **重复 id** | 页头人数控件与座位面板都叫 `id="players"`,`getElementById` 只返回第一个 → 渲染座位时把页头控件清空,表现为"人数下拉框空白、座位面板没内容" | id 必须唯一;用例 `HTML-01`~`HTML-04` |
| **就地修改 + 帧数组** | 回放时间轴每帧都显示终局:`apply` 就地修改状态,重复 push 同一个对象 | 每帧 `cloneState` |
| **原生 select 渲染** | 某些浏览器下"有选项但显示空白" | 人数改为按钮组 + 纯文本回显 |
| **中文引号截断 JS 字符串** | 一行提示文案里写了 `"…「没看牌就被干掉」…"` 之外还用成对中文引号 `"…"`,直接把字符串截断 → **整个 `app.js` 解析失败 → 所有按钮消失**(表现为"人数又丢了") | 用例 `HTML-07`:所有前端 JS 必须通过 `node --check` |
| **顶层控件绑定顺序** | 任一控件缺失时,顶层 `$("id").onchange = …` 抛错会中断脚本,后续的 `boot()` 不再执行 → 核心界面不渲染 | `boot()` 提前执行 + 启动自检(缺控件时明确提示"请 Ctrl+F5") |

## 规则实现

| 陷阱 | 症状 | 修法 / 用例 |
| --- | --- | --- |
| **同一规则只写在 validate 里** | 新增"比牌最早轮次 / 保护未看牌者"时只改了 `validateCompare`,没同步 `enumerateActions` → AI 从"合法动作列表"里选了 COMPARE、`apply` 却拒绝 → **对局在第 2 局卡死** | 抽出共用判定 `compareRuleBlock`,`validate` 与 `enumerateActions` 都走它;用例 `E2E-25`:**枚举出的每个动作都必须能被 apply 接受** |
| **同一概念在多层各写一遍** | "付得起吗"曾分别写在:引擎支付校验 / 前端按钮禁用 / AI 决策逻辑 —— 欠债模式只改了引擎,于是前端按钮仍是灰的、AI 仍集体弃牌 | 三处统一:`canPay`(引擎)→ `v.allowDebt`(前端)→ `effectivePoints`(AI)。用例 `AI-10`/`AI-12`/`HTML-06` |
| **参考量取错** | "名义筹码"取的是用户可任意设小的"初始积分",于是初始积分设 1 时 AI 又退化成全员弃牌 | 改成 `max(初始积分, 20 × 底注)` —— 参考量必须与游戏刻度绑定。用例 `AI-12` |
| **校验尺度取错** | 欠债预警按"底注 ×50"判定,对大额长局(初始 1000 / 阈值 250000)误报 | 改按**胜负差**判定。用例 `CFG-11` |
| **兜底量不随注码增长** | 欠债模式下"名义筹码"兜底到**初始积分**就封顶;长局 M 变大后**一注**就超过它 → 判定为"付不起" → 直接弃牌,连手里是四条/同花顺都不看。真实事故:底注 53 / 初始 2888 / M=32,跟注 3392 > 2888,EQB 弃掉葫芦 | 欠债模式下"付得起吗"交给**引擎**决定(`canAfford`:允许欠债即视为付得起),AI 只按牌力决策;非欠债模式保留闸门(那时付不起确实只能弃)。用例 `AI-14` |
| **rollout 被步数上限截断** | 蒙特卡洛的 rollout 上限 100 步 < 一手实际所需(实测某手还要 111 步)→ 半局的"已投入筹码"被当成纯亏损 → 手牌越强账面越亏 → 四条被算成期望为负而弃掉。单挑触发不到(手牌短),只在 6 人长局发作 | 上限调到够一手打完(600)+ **未结算的样本一律剔除** + 无有效样本时退回启发式。用例 `AI-13` |

## 数据与结论

| 陷阱 | 症状 | 修法 |
| --- | --- | --- |
| **样本量不足** | 20 场得出"换兜底 +197 更好";200 场配对评估后是**显著更差**。30 桌联赛 ZeroB 第一;100 桌后掉到第四 | 结论需 ≥100 场;**配对评估**(两策略跑同一批种子、逐场做差值)+ t 值判断。工具 `examples/zerob-eval.ts` |
| **口径混淆** | 同一 ZeroB:4 人局 −30/场,6 人桌 +401/场(30 桌) / +106(100 桌);Sam 单挑是基准,多人桌却垫底 | 报数据必须写清人数口径与对手 |

## 工具链

| 陷阱 | 症状 | 修法 |
| --- | --- | --- |
| **静默替换失败** | 用 `String.replace` 批量改代码时锚点写错 → 无声无息什么都没改(出现过数次,包括"改了但没生效"的界面提示) | 关键替换必须**先断言匹配次数**,改完再复查字符串 |
| **测试与实际产物不一致** | 测试套件全绿,但浏览器加载的 `app.js` 有语法错误 —— 因为测试不加载它 | 能运行的产物都要过闸门:`HTML-07`(前端 JS 语法)+ 端到端探针(起服务、抓实际下发内容) |
